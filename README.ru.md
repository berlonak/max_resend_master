# Мост MAX ⇄ Telegram

Двусторонний «пересыльщик»: бот в MAX и бот в Telegram сидят каждый в своей
группе/канале, сохраняют сообщения и файлы в базу на сервере и пересылают их на
другую платформу с подписью «от кого / откуда / когда».

Версия учитывает факт-чек документации MAX от 03.08.2026.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполнить токены и ID чатов
python main.py
```

## Если при запуске падает с ConnectionError

```
ConnectionError: Unexpected peer connection
```

Это **не ошибка моста** — падение происходит внутри Python, до выполнения его
кода. На Windows нет системного `socketpair()`, и asyncio эмулирует его
TCP-соединением на localhost, проверяя, что соединение своё, по адресам сторон.
Перехватчики локального трафика адреса подменяют, и проверка срабатывает ложно.
Открытый баг CPython #129676.

Диагностика:

```bash
python diagnose.py
```

Скрипт покажет реальные адреса сокетов и переберёт способы обойти проблему.

**Обходится автоматически.** `winfix.py` подключён в начале `main.py`, сам
определяет поломку и подбирает рабочий способ:

1. стандартный socketpair — если всё исправно, ничего не трогается;
2. IPv6 (`::1`) — многие перехватчики работают только с IPv4;
3. IPv4 с подтверждением секретным токеном вместо сравнения адресов;
4. IPv6 с подтверждением токеном.

Проверка безопасности не отключается: там, где сравнение адресов не работает,
стороны обмениваются случайным 32-байтовым секретом. Посторонний процесс его не
угадает, а честный перехватчик просто передаст байты дальше.

**Убрать причину полностью (Proxifier).** Выключать его целиком не нужно —
достаточно исключить Python: `Profile → Proxification Rules → Add`,
Applications: `python.exe; pythonw.exe` (полный путь к своему интерпретатору),
Action: **Direct**, правило поднять выше остальных. Для антивирусов, VPN и
Fiddler/Charles/Burp — аналогично добавить `python.exe` в исключения.
При повреждённых сетевых фильтрах помогает `netsh winsock reset` от
администратора с перезагрузкой.

## Если падает с CERTIFICATE_VERIFY_FAILED

```
[SSL: CERTIFICATE_VERIFY_FAILED] unable to get local issuer certificate
```

MAX работает на TLS-сертификатах **НУЦ Минцифры России**. Их корневого
сертификата нет ни в Windows, ни в macOS, ни в наборе `certifi`, поэтому
проверка не проходит. Требование к trust store прописано в документации MAX.

Решение — одна команда:

```bash
python install_ru_certs.py
```

Скрипт скачает корневой и промежуточный сертификаты в папку `certs/` рядом с
проектом и сразу проверит соединение с `platform-api2.max.ru`. Менять что-либо
в системе не нужно. Официальный источник, если захотите скачать вручную:
https://www.gosuslugi.ru/crt — файлы положить в `certs/`.

**Важная тонкость.** `httpx` по умолчанию доверяет только набору `certifi` и
**не смотрит в хранилище Windows**. Поэтому установленный в систему сертификат
Минцифры сам по себе Python не помогает. Мост собирает доверие явно
(`sslsetup.py`), складывая вместе:

1. системное хранилище (в Windows — хранилища CA и ROOT);
2. набор `certifi`;
3. всё из папки `certs/`;
4. файл или папку из переменной `MAX_CA_BUNDLE`.

Это же лечит ситуацию, когда TLS вскрывает антивирус или корпоративный прокси —
их корневой сертификат обычно уже стоит в хранилище Windows.

Посмотреть, кто именно выдал сертификат, можно диагностикой:

```bash
python diagnose.py
```

Она покажет издателя (Минцифры, антивирус, корпоративный прокси) и сравнит,
как видят сертификат `certifi` и мост.

Переменная `SSL_VERIFY=false` отключает проверку целиком. Использовать только
для отладки: трафик станет уязвим к перехвату, и мост об этом предупредит в логе.

## Если бот не видит сообщения в группе MAX

Запустите диагностику стороны MAX:

```bash
python max_check.py          # проверки + прослушивание 90 секунд
python max_check.py 30       # прослушивание 30 секунд
python max_check.py 0        # только проверки
```

Скрипт ничего не меняет, только читает, и проверяет по порядку:

1. **Бот** — отвечает ли `/me`.
2. **Webhook-подписки** — если подписка активна, MAX шлёт события на неё, и
   long polling остаётся пустым. Частая причина тишины.
3. **Чат из .env** — существует ли, как называется, группа это или канал.
4. **Права бота** — есть ли `read_all_messages`, админ ли бот.
5. **Чтение сообщений** — прямая проверка `GET /messages`, видит ли бот содержимое.
6. **Живое прослушивание** — вы пишете в группу, скрипт показывает сырое событие
   и все встреченные `chat_id`, сверяя их с вашим `MAX_CHAT_ID`.

Шестой пункт отвечает на вопрос «правильный ли ID в .env» окончательно: если
нужного ID нет среди пришедших, скрипт покажет верный.

**Самая частая причина** — у бота нет права `read_all_messages`. Выдать его:
откройте группу в MAX → Настройки → Участники → найдите бота → назначьте
администратором → включите доступ к чтению всех сообщений → перезапустите мост.

Для подробного разбора можно включить сырые события в логе моста:

```
LOG_LEVEL=DEBUG
```

## Если Telegram отвечает «chat not found»

Формат ID в Telegram зависит от типа чата — это самая частая ошибка:

| Тип чата           | Формат ID          | Пример          |
|--------------------|--------------------|-----------------|
| обычная группа     | `-<id>`            | `-5551350630`   |
| супергруппа, канал | `-100<id>`         | `-1005551350630`|
| личный чат         | `<id>`             | `5551350630`    |

Префикс `-100` бывает **только** у супергрупп и каналов.

⚠️ **Не угадывайте формат по типу чата.** Telegram молча превращает обычную
группу в супергруппу — например, когда вы назначаете бота администратором. То,
что группа создавалась обычной, ничего не гарантирует. Единственный надёжный
способ — узнать ID у самого бота через `tg_check.py`.

Подобрать правильный ID:

```bash
python tg_check.py           # проверки + прослушивание 90 секунд
python tg_check.py 0         # только проверки
```

Скрипт перебирает варианты ID, показывает название и тип найденного чата,
проверяет права бота, отправляет пробное сообщение и в конце ловит настоящий
`chat.id` из живого события. Перед запуском остановите `main.py` — Telegram не
даёт двум процессам читать обновления одного бота.

**Privacy Mode.** По умолчанию бот в обычной группе видит только команды и
ответы себе, а обычные сообщения ему не приходят — направление Telegram → MAX
работать не будет. Отключить: `@BotFather` → `/setprivacy` → `Disable`, после
чего **удалить бота из группы и добавить заново** — иначе настройка не
применится. Альтернатива — сделать бота администратором группы.

## Что уже сделано

- Текст, фото, видео, аудио, голосовые, документы, стикеры, GIF — в обе стороны.
- Альбомы: MAX присылает одним сообщением, Telegram — частями (собираются агрегатором).
- Ответы (reply) — тред восстанавливается по mapping.
- Архив сообщений и медиа в SQLite + файлы на диске, с SHA-256.
- **Идемпотентность**: повторная доставка Update не создаёт дубль.
- **Анти-петля**: по mapping и по ID собственных ботов.
- **Лимиты частоты**: 2 сообщения/сек на чат, ~25 rps суммарно, порядок внутри чата.
- **Разбиение длинного текста**: MAX 4000, Telegram 4096, подписи к медиа 1024.
- **Нарезка альбомов**: Telegram принимает по 10, MAX — до 12 вложений.
- **Разделение файлов и медиа**: MAX запрещает смешивать `file` с `image`/`video`.
- **Контроль размеров**: лимиты MAX (image 50 МБ, video 250 МБ, audio 256 МБ, file 4 ГБ)
  и Telegram (20 МБ скачивание, 50 МБ отправка в облачном API).
- **Повторы**: 429, 5xx и `attachment.not.ready` — с экспоненциальной задержкой;
  400/401/403 — без повтора.
- Видео MAX: если пришёл только токен, url добирается через `GET /videos/{token}`.

## Ключевые требования платформ

**MAX.** Домен `https://platform-api2.max.ru` обязателен с 19.07.2026.
Авторизация — только заголовком `Authorization: <ТОКЕН>`, голым токеном, без `Bearer`
и не в query string. Боту нужно право **`read_all_messages`**, иначе он будет
состоять в чате, но не получать сообщения — это самая частая причина «в личке
работает, группу не видит». Мост проверяет это право при старте и предупреждает.
Список чатов через API получить нельзя: `chat_id` берётся из событий и хранится у себя.

**Telegram.** Бот должен быть админом группы либо иметь выключенный Privacy Mode.
Боты **не видят сообщения других ботов** — это ограничение Bot API. Старую историю
через Bot API получить нельзя: мост работает с момента подключения.

## Что честно нельзя обещать

- Удаление Telegram → MAX: в Bot API нет события об удалении обычного сообщения.
- Перенос файлов MAX 2–4 ГБ в Telegram — даже локальный Bot API Server даёт максимум 2000 МБ.
- Нативный перенос произвольного стикера: TGS/WebM конвертируются или уходят картинкой/файлом.
- Реакции и опросы — общего эквивалента между платформами нет.
- Реальный автор за анонимным админом или постом канала — платформа его не раскрывает.

## Дальнейшие шаги (в порядке приоритета)

1. **Webhook вместо long polling.** Сейчас MAX слушается через `/updates` — это режим
   для разработки. Для production нужен `POST /subscriptions` с HTTPS на 443,
   проверкой заголовка `X-Max-Bot-Api-Secret` и ответом `200` за 30 секунд.
   MAX повторяет доставку до 10 раз и может удалить подписку после 8 часов неудач.
   Клиент уже умеет `create_subscription()`.
2. **Edit/delete.** Методы `edit_message()` / `delete_message()` в клиенте есть,
   mapping хранит все части — осталось подключить обработчики
   `message_edited` / `message_removed`.
3. **FFmpeg** для голосовых (OGG/OPUS → MP3/M4A) и статических стикеров (WebP → PNG).
4. **PostgreSQL + Redis** вместо SQLite, если нагрузка вырастет.

## Структура

```
config.py       конфигурация из .env
models.py       единая модель входящего сообщения
db.py           SQLite: дедуп, архив, mapping
utils.py        время, подписи, разбиение текста, скачивание файлов
ratelimit.py    лимиты частоты (глобальный + пер-чатный) и порядок
max_client.py   REST-клиент MAX Bot API
bridge.py       ядро пересылки
main.py         слушатели, сборка альбомов, запуск
winfix.py       обход бага socketpair на Windows
sslsetup.py     сборка доверия TLS (сертификаты Минцифры и прочие)
install_ru_certs.py  загрузка корневых сертификатов НУЦ Минцифры
diagnose.py     диагностика окружения (Windows, сеть, TLS)
max_check.py    диагностика MAX (права, подписки, chat_id, живые события)
tg_check.py     диагностика Telegram (подбор chat_id, права, Privacy Mode)
```

## Юридическое

Вы храните чужую переписку и файлы — это обработка персональных данных (152-ФЗ).
Нужно согласие участников и предупреждение в описании чатов. Создание и публикация
ботов MAX требует профиля разработчика/бизнеса и верификации — проверяйте условия
в кабинете MAX, это не только технический токен, но и организационный доступ.
